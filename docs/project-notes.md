  폭이 최대인 FillWidth 상태에선 세로를 못 키웁니다. 그래서 `RouteImageInline(zoom=1.5f)`로
  폭을 1.5배 키우고 넘치는 폭은 가로 스크롤(오른쪽 주행계·전반/후반 통계표가 스크롤 밖).
  세로 공간은 `ModalBottomSheet(skipPartiallyExpanded = true)`로 확보. 되돌리려면 zoom을 1f로.
  펼침 오른쪽 패널은 zoom 1f 유지 — 이미 크고 가로 스크롤이 필요 없습니다.
- **인라인 행로표 배율: 본선 1.8배 / 지선 1.5배**(v1.6.8, 접힘만). 원본 비율이 본선 ~2.1:1,
  지선 ~1.41:1로 달라서 공통 1.5배면 본선만 납작해 보입니다("지선만 커졌나?"). 접힘 폰 411dp
  기준 본선 세로 ~335dp(1.5배였을 땐 ~282dp), 지선은 ~423dp로 종전과 동일.
  `MainCalendarScreen.kt`의 `val zoom = if (!compact) 1f else if (day.duty.isBranch) 1.5f else 1.8f`.
- **전체화면 행로표 90도 회전**(v1.6.9). `RouteImageDialog`에서 화면이 세로(`maxHeight > maxWidth`)이고
  이미지가 가로형이면 `Bitmap.createBitmap(..., Matrix().postRotate(90f), true)`로 회전본을 만들어 표시.
  `remember(src, portrait)`로 캐시하고 **원본은 recycle 안 함**(`remember(asset)`가 계속 붙들고 있어
  접힘↔펼침 전환 때 다시 필요). 접힘 1080x2400에서 본선은 폭맞춤 대비 표가 약 2배(긴 변 411→850dp),
  지선은 1.41배. 펼침(2208x1840)은 가로가 넓어 조건에서 자동으로 빠져 기존 그대로.
  제목·닫기 버튼은 `BoxScope.align`이라 회전과 무관하게 정방향. 인라인(`RouteImageInline`)은 안 건드림.
  기기를 실제로 돌리면(orientation 잠금 없음) 가로가 돼 회전이 저절로 풀린다.
- **달력 칸 폰트·공휴일 이름 배치**(v1.6.8 → v1.6.10에서 수치 재조정). 날짜 숫자
  `7.5 → 7(v1.6.8) → 6.5sp(v1.6.10)`, big은 `9.5 → 9 → 8.5sp`. 날짜 알약 여백
  `horizontal 4→2dp` / `start 3→2dp`로 이름에 폭을 양보. 이름은 `HolidayTag`가 폭을 넘치면
  0.92배씩 자동 축소(하한 5sp) — 다이아 칩·시각표 카드와 같은 방식.
  배치는 **칸 폭**으로 갈립니다(`CalendarGrid`의 `nameBelow = 칸폭 < 60dp`, v1.6.8엔 45dp):
  **임계를 45→60dp로 올린 이유**(v1.6.10) — 폴더블 커버 화면은 폭이 320~411dp라 칸이 45~54dp,
  45dp 임계에 안 걸려 이름이 날짜 옆에 남았고 실기기에서 `광복절`이 계속 잘렸습니다.
  60dp면 폰 폭 전 구간이 아랫줄로 갑니다(에뮬 360dp·411dp 모두 확인).
  아랫줄은 칸 전체 폭을 쓰고 세로는 남아돌아 아래 요소를 안 밉니다.
  **칸 높이(`big`)로 가르면 안 됩니다** — 5주 달(7월)과 6주 달(8월)에서 값이 뒤집혀 월마다 배치가 달라집니다.
