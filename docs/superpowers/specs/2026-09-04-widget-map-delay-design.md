## 1차 — v1.6.88

### A. 위젯 (Glance, `widget/`)

현재: `DutyWidget` 하나, `duty_widget_info.xml` targetCell 4x1. `SizeMode.Responsive(TINY·MID_SHORT·MID·WIDE_SHORT·WIDE)`로
2x1/3x1 레이아웃은 이미 있지만 **런처 위젯 목록에는 4x1 한 항목만** 보인다. 폰 글자 배율(카스 ≈1.3)을 계산에 안 넣어 가끔 잘린다.

변경:
1. **위젯 목록에 3항목** — `DutyWidgetReceiver2`(targetCell 2x1) · `DutyWidgetReceiver3`(3x1) · 기존(4x1). 세 리시버가 **같은 `DutyWidget` 클래스**를 쓴다(내용은 `LocalSize`로 결정). 각자 `duty_widget_info_{2,3,4}.xml` + 미리보기 레이아웃 3종. 매니페스트에 리시버 2개 추가. 기존 4x1 위젯을 이미 놓은 사용자는 그대로 유지돼야 한다(기존 리시버 이름 불변).
2. **크기별 내용**
   - 2x1: 오늘 근무(크게) + 아래 한 줄 "출근 07:47" 또는 "편승 12:36"(있는 것 하나, 출근 우선). 오늘이 휴무/비번이면 "내일 출근 …".
   - 3x1: 오늘·내일·모레 3칸(요일+날짜 / 근무). 오늘 칸 강조.
   - 4x1: 7일 스트립(지금과 같음) + 높이가 되면 부제.
3. **색 = 앱 달력과 동일**. 칸 배경/글자색을 `DutyType`별로: 주간(기본) · 야간 보라 · 휴무 빨강 · 대기 노랑 · 비번 회색 · 지선 동일 규칙. 색 값은 `util/MonthImage.kt`의 근무색 표(`DutyType → 배경/글자`)를 **그대로 재사용**(한 곳). 오늘 칸은 기존처럼 primary 강조 유지.
4. **글자 배율 대응**: `LocalContext.current.resources.configuration.fontScale`을 읽어 `narrow`/`tall` 판정을 `dp / fontScale`로 하고, 배율 ≥1.3이면 글자 한 단계 축소. 목표: 배율 1.0·1.3·1.5, 접힘(1080x2400)·펼침(1968x2184) 모두 **잘림 0**.
5. 데이터 포맷: `KEY_WEEK` 레코드를 `요일|일자|근무|빨강|타입|시각`으로 확장(뒤 두 칸 선택 — 4칸만 있어도 파싱). `타입` = `DutyType.name`, `시각` = 그 날 출근 또는 편승 시각(`HH:mm`, 없으면 빈칸). 채우는 곳은 기존 `DutyWidgetWorker` 한 곳.

검증: 에뮬에서 세 크기 × 배율(1.0/1.5) × 접힘/펼침 스크린샷, 위젯 목록에 3항목이 뜨는 화면, 기존 4x1이 남아 있는지.

### B. 2호선 실시간 지도 (`presentation/live/MainLineMap.kt`)

1. **방향 필터 칩** `[내선 | 외선 | 전체]`를 하단 상태바 옆에. 기본값 = **내 열차 방향**(`MyTrain`이 준 열차의 `inner`), 내 열차가 없으면 전체. 선택은 `remember`(회전/재진입 시 기본으로 복귀해도 됨 — `rememberSaveable` 함정 때문). 내 열차는 어느 모드든 항상 그린다.
2. **글자 확대**: 필터가 켜져 배지가 한쪽만 남는 동안 역명 11.5→13.5sp(펼침 14→16sp), 열번 배지 10.5→12sp(펼침 13→14.5sp). 전체 모드에서는 지금 크기 유지. 겹침 판정(SAT)은 그대로 재사용 — 확대 후에도 겹침 0이어야 한다.
3. **움직임 (8-b)**: 열번별 `Animatable(위치)` — 새 스냅샷의 위치로 **1초 tween**. 스냅샷 사이에는 `역간 소요시간`(아래 C의 시간표에서 같은 열번의 A역 LEFTTIME → B역 ARRIVETIME 차; 없으면 120초)으로 **다음 역 95% 지점까지만** 선형 전진하고, 다음 스냅샷이 오면 다시 tween. 절대 다음 역을 넘어가지 않는다. 화면이 안 보일 때(onPause) 애니메이션 중단.
4. **내 열차 상단 문구**: `내 열차 2039 · 외선 · 동대문역사문화공원 진입 · +2분 지연 · 다음 역 3분 후`. 지연/다음역은 C에서 계산, 시간표에 열번이 없으면 그 두 토막만 생략.

검증: 세로·가로·펼침에서 필터 3모드 스크린샷, 겹침 0, 실데이터(또는 실응답 재생)로 움직임 캡처(연속 3장), 상단 문구 지연 표기.

### C. 2호선 역별 시간표 내장 + 지연 계산 (신규 `domain/model/Line2Timetable.kt`, `tools/fetch_line2_timetable.py`)

- **출처**: 서울 열린데이터광장 `SearchSTNTimeTableByIDService/{start}/{end}/{STATION_CD}/{WEEK_TAG}/{INOUT_TAG}` (2026-09-04 기존 인증키로 정상 응답 확인, 홍대입구 평일 내선 240편). 필드: `TRAIN_NO, ARRIVETIME, LEFTTIME, ORIGINSTATION, DESTSTATION, WEEK_TAG(1평일 2토 3휴일), INOUT_TAG(1 내선 2 외선 — 스크립트가 실데이터로 재확인해 주석에 남길 것), EXPRESS_YN, BRANCH_LINE`. 역 코드는 `SearchInfoBySubwayNameService/1/5/{역명}`에서 `LINE_NUM=02호선` 행의 `STATION_CD`. 자정 넘김은 `25:00:00` 표기.
- **스크립트**: 본선 43역(`Line2Stations.MAIN`) + 지선 4역(도림천·양천구청·신정네거리·까치산) × WEEK_TAG 3 × INOUT_TAG 2 ≈ 282회 호출(키 한 개 하루 한도 안, `BranchLive.API_KEYS` 마지막 키 사용). 출력 `app/src/main/assets/timetable/line2.json` 한 파일: `{ "fetched": "2026-09-04", "stations": {"역명": "코드"}, "rows": [[weekTag, inout, stationIdx, "trainNo", arriveSec, leftSec], …] }`(초 단위 정수, 목표 ≤ 600KB). 갱신은 **코디네이터가 다이아 개정 때 스크립트 재실행**(운영 부담 0, 7번 결정). 시간표 판 날짜를 설정 화면 맨 아래에 "열차 시간표 2026-09-04판"으로 표시.
- **로더**: `Line2Timetable`(lazy, 한 번 파싱, `Map<(weekTag,inout,trainNo), List<Stop>>`). 오늘의 WEEK_TAG = 앱의 기존 휴일 판정(토=2, 공휴일/일=3, 그 외 1).
- **지연 계산** (`fun delayMinutes(trainNo, statnNm, trainSttus, now): Int?`): 실시간 상태를 시간표 사건에 맞춘다 — `1 도착 → ARRIVETIME`, `2 출발 → LEFTTIME`, `0 진입 → ARRIVETIME − 30초`, `3 전역출발 → 전역 LEFTTIME`. `지연 = now − 사건시각`, 분으로 반올림, |지연| < 1 → "정시", 양수 "+N분 지연", 음수 "N분 빠름". 시간표에 열번·역이 없으면 `null`(표시 생략). 25시 표기는 익일로 접는다.
- **다음 역 도착**: `다음 역 ARRIVETIME + 지연 − now`(API 호출 0). 0 이하면 "곧 도착".
- **역간 소요시간**(B-3용): 같은 열번의 인접 두 역 `LEFTTIME→ARRIVETIME` 차, 없으면 120초.
- 테스트: 소형 fixture(역 3개·열번 2개)로 지연 4사건·25시 접기·다음역·소요시간·미등록 열번 null.

## 2차 — v1.6.89

### E. 월 메모 화면 맨 위 주별 근무시간 (`presentation/calendar/MemoListSheet.kt` + 신규 `domain/usecase/WeeklyHours.kt`)

- 표시: `9월 · 1주 50.1h · 2주 42.5h · 3주 32.5h · 4주 54.0h`(한 줄, 넘치면 두 줄). **52.0h 초과 주는 빨간색 + 굵게**. 5주가 있는 달은 5주까지.
- 주 = **월~일**. 그 달에 속한 날만 합산(월초·월말의 걸친 주는 그 달 날짜만 — 라벨에 `(1~4일)`처럼 날짜 범위 표기).
- 하루 근무시간:
  - 본선 주간/야간, 지선: 행로표 `계`(`RouteTable.forMain/forBranch(...).totalWorkTime`, 야간은 조합별). **야간은 시작일 주에 전부.** `~`(비번) = 0.
  - 대기(대1~13): `Bundled.STANDBY` 출퇴근 차(예: 대1 7:00~16:00 = 9.0h). 지대 동일 규칙.
  - 휴무·비번·연차·보상·대휴·촉연·기타휴가 = 0.
  - 근무변경 `충당/대기충당/교체 + 근무번호`: 채운 근무의 시간. 번호 없으면 0 + 미포함 표시.
  - 교육·회행·지근(번호 없는 지정근무)·직접입력 등 시간 미정 = 0, 그 주 옆에 `(교육 1일 미포함)` 식으로 표기.
- 근무변경·메모 저장 즉시 재계산(달력 상태에서 파생, 저장 없음). 순수 함수 + 테스트(경계: 월 걸친 주, 야간 시작일 귀속, 52 초과 색, 미포함 꼬리표).

### F. 관리자 공지 카드 (Firestore `notices/{id}`)

- 문서: `title(≤40자) · body(≤500자) · from(yyyy-MM-dd) · to(yyyy-MM-dd) · createdAt · author("admin")`. 규칙: 읽기 signedIn, 쓰기 관리자만(식단표 `menus` 쓰기와 같은 조건·키 검증). 규칙 배포는 코디네이터.
- 관리자 화면(식단표 관리 옆)에 "공지 쓰기/목록/삭제".
- 달력 맨 위 카드: 기간 안의 공지 중 최신 1건, 제목 + 본문 2줄, 탭하면 전체. **닫기(X)**하면 그 공지 id를 로컬에 기억해 다시 안 뜸. 새 공지는 다시 뜸.
- 위젯에는 넣지 않는다(3번 결정).
